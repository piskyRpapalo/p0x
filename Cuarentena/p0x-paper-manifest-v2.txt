#### 2. EL REPOSITORIO CRÍTICO: codice-emancipacion-atomica
El repositorio github.com/piskyRpapalo/codice-emancipacion-atomica es el contenedor exclusivo de tus scripts de automatización Bash y utilidades del sistema [132]. Aunque se encuentra desactualizado, representa la espina dorsal operativa que gestiona la inicialización física, los demonios del sistema y los reflejos térmicos del nodo [42, 132].

El núcleo de este repositorio es la implementación física de la Constitución de p0x, ejecutada a través de `verify_pow.sh` [5, 112]. Este script de arranque crítico realiza las siguientes validaciones secuenciales obligatorias [5]:
1. Cálculo del checksum de los binarios del sistema y el núcleo de Aurelius [5].
2. Verificación de la firma criptográfica detached del manifiesto del nodo (`manifest.json.sig`) utilizando la clave pública `sovereign_ed25519.pub` [5].
3. Ejecución de un análisis de consistencia de datos relacionales en la base de datos SQLite (`PRAGMA integrity_check`) [5].
4. En caso de detectarse cualquier discrepancia, corrupción o firma corrupta, el script aborta la secuencia con exit code 1, bloquea la interfaz web y desconecta las APIs de comunicación para salvaguardar el metal [5].

La reestructuración activa del "codice-emancipacion-atomica" busca depurar los scripts antiguos y adecuarlos a las deudas técnicas de hardware e infraestructura halladas en el censo (remediación del sensor térmico mediante k10temp, el enlace huérfano de sínodo y la implementación de la cola de inferencia) [43, 44, 137].

Para asegurar una transición inmaculada sin regresiones de software ni riesgos en el runtime activo, la construcción del nuevo entorno se guiará bajo el **Contrato de Sistema Paralelo**:
*   **Aislamiento de Espacio de Trabajo**: Toda la nueva infraestructura, el nuevo `verify_pow.sh` y las utilidades lógicas vivirán exclusivamente dentro de `~/p0x-soberano/`.
*   **Inviolabilidad del Entorno Original**: **NUNCA** se escribirá en las rutas activas de producción: `~/aurelius/`, `~/hexelion/`, `~/p0x/`, ni `~/.ollama/`.
*   **Lectura de Resiliencia**: El sistema paralelo leerá los archivos de configuración o el estado del sistema original si es estrictamente necesario, pero su persistencia, bases de datos y ejecución de red se desplegarán de forma autónoma.
*   **Verificación en Frío**: Se garantiza la funcionalidad independiente del sistema paralelo manteniendo intactas las deudas, logs y operaciones del original para comparación comparativa antes del merge final de producción.

#### 4. ARQUITECTURA MEDALLÓN EN DISCO (AURELIUS CORE)
La persistencia local-first de Aurelius Core se asienta sobre tres capas físicas inmutables en disco para mitigar el desgaste de escritura (Write Wear) de las memorias flash y organizar de forma segura la telemetría y el engramaje de aprendizaje [12, 140]:
*   **CAPA BRONCE (data/bronze/)**: Log incremental JSONL inmutable en disco que registra interacciones de chat crudas, trazas y telemetría de sensores en caliente [12, 141]. La escritura en disco se pausa de manera automática durante las inferencias complejas de Ollama para no asfixiar el bus de E/S del procesador [12, 141].
*   **CAPA SILVER (proposals_YYYY-MM.jsonl)**: Archivo consolidado mensual de propuestas cursadas por línea [12, 142]. Está optimizado para realizar búsquedas eficientes por bloques o cursores de 10-20 registros en arquitecturas de bajo consumo ARM sin saturar la memoria RAM [12, 142]. Alberga el "Modo Cosecha" (Harvest Mode) para validaciones intermedias [12, 142].
*   **CAPA GOLD (gold_chain.jsonl)**: El Ledger de la Verdad Firmada [12, 143]. Cada bloque de conocimiento ("engram") estructurado obligatoriamente en 4 campos (What, Why, Where, Learned) se concatena criptográficamente con el hash SHA-256 del bloque anterior utilizando triggers nativos en C dentro de SQLite [12, 22, 111, 143]. La base de datos unificada (~/.aurelius-p0x/db/aurelius_state.db) se deriva de esta cadena [12, 143].

#### 6. LA NECRÓPOLIS DE SILICIO: SISTEMAS VETADOS POR LA DOCTRINA
Para preservar la eficiencia energética, la soberanía de los datos y evitar el desgaste físico de las unidades de almacenamiento, p0x cuenta con un cementerio de tecnologías prohibidas:
1.  **Electron y Go (de la pila Anytype heredada)** [17, 159]: Vetados por consumo de RAM excesivo (>300MB base) e ineficiencia extrema de hilos sobre procesadores ARM de bajo consumo [17, 159]. Reemplazados por scripts de Python ultraligeros que sincronizan bases de datos SQLite cifradas con AES-CFB [17, 159].
2.  **Google Coral Dev Board**: Devuelto por limitaciones de rendimiento y hardware [110]. Reemplazado por Yahboom Jetson Orin Nano Super de 8GB (67 TOPS estables) [110].
3.  **Daemon immudb** [22, 159]: Su colector de basura y procesamiento de hashes generaba picos térmicos agudos en los procesadores ARM de Le Jardin [22, 159]. Reemplazado por la inyección matemática de un trigger en C que calcula los árboles de Merkle internamente en SQLite [22, 159].
4.  **Servidores Flask monohilo y Puertos TCP Crudos de dump1090** [21, 23, 159]: Eliminados por falta de cifrado, vulnerabilidad ante inyecciones remotas de telemetría aérea falsa e interbloqueos [21, 23, 159]. Reemplazados por el gateway asíncrono de FastAPI restringido a localhost [8, 21, 23, 159].
5.  **El Retiro de Andamios (Scaffolding Faded)** [11, 26, 154, 161]: Tras la finalización de una misión formativa de Aurelius, verify_pow.sh comprime las plantillas formativas (_scaffold/) en un archivo .tar.gz de solo lectura y las elimina físicamente del espacio de desarrollo (rm -rf), erradicando residuos y forzando la independencia del operador [11, 26, 126, 154, 161].
