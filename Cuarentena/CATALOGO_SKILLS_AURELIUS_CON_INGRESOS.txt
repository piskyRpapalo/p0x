REGLAS DE CLASIFICACIÓN
-----------------------
BRONCE  → Disponible en LITE (8 GB RAM). Barrera cero. Pedagogía pura.
          Sin FAISS, sin criptografía, sin red privada. Solo Python, JSONL,
          HTML/JS vanilla, y el modelo que elija el usuario.

PLATA   → Requiere PRO o progreso en misiones. Añade persistencia estructurada,
          evaluación, FAISS, Gold poblado, o embeddings. No requiere red ni
          criptografía de infraestructura.

ORO     → Requiere PRO + infraestructura avanzada: criptografía (Ed25519,
          AES-256-GCM), red privada (Tailscale), transferencia entre nodos,
          Mesh, o 32 GB+ RAM para enjambres grandes.

INVARIANTES DEL PROYECTO (aplicables a TODAS las skills):
  - El modelo lo elige el usuario; el proyecto nunca lo fija.
  - PROHIBIDO eval/exec/subprocess con texto generado por el modelo o el usuario.
  - CERO direcciones IP, nombres de host, credenciales en código o config versionado.
  - Toda fricción debe ser predicción o recuperación; si solo impone coste, no entra.
  - IronClaw: el sistema propone; el humano ejecuta y firma.
  - Honest Math: los números salen siempre de código determinista; el modelo solo redacta.
  - Portapapeles Soberano: sin botón de copiar; selección manual obligatoria.
  - Command Guard: parser determinista (regex/AST); NUNCA el LLM audita seguridad.
  - Sin dependencias nuevas sin justificar.

SKILL B.01: PERFILES DE CONFIGURACIÓN (PRO / LITE)
---
Medallón: BRONCE
Descripción: El servidor acepta --perfil con dos valores. El perfil NO fija el
  modelo; fija el contrato de recursos esperados (RAM mínima, contexto), la
  interfaz de escucha (loopback para LITE, red privada configurable para PRO),
  y qué capacidades se declaran disponibles.
Mecánica: Al arrancar, el servidor lee el perfil de un argumento CLI. Carga
  config.lite.json o config.pro.json (no versionados, ejemplos sí). El perfil
  expone en /api/capabilities qué skills están disponibles para ese contrato.
Valor: Un solo código, dos contratos honestos. LITE es honesto con hardware
  modesto; PRO aprovecha el nodo soberano sin mentir al clonador.
Requisitos técnicos: Argumento CLI en el servidor. Dos archivos de ejemplo de
  configuración. Parser de JSON.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Véndelo como "Aurelius Profiles SDK" a bootcamps y plataformas EdTech. Ellos 
  integran tu sistema de perfiles (--lite / --pro) para ofrecer a sus alumnos 
  dos contratos de recursos honestos. Cobras licencia por nodo desplegado.
  El valor: sus alumnos saben exactamente qué hardware necesitan antes de 
  empezar, reduciendo churn por frustración técnica.

Reglas aplicadas: El modelo es elección del usuario. Sin direcciones hardcodeadas.

SKILL B.02: DECLARACIÓN HONESTA DEL MOTOR
---
Medallón: BRONCE
Descripción: Al arrancar, el servidor consulta al motor de inferencia qué modelo
  tiene cargado, su ventana de contexto, y su ubicación. Expone tres estados
  derivados del endpoint configurado: SOBERANO (loopback local), DELEGADO (otra
  máquina del usuario por red privada), HUESPED (tercero). Visible en la UI de
  forma permanente, no en un menú.
Mecánica: GET al endpoint /api/tags de Ollama (o equivalente). Si no responde,
  valor = NO_DATA; nunca supuesto. La topología se deriva del hostname en la URL
  del endpoint: localhost/127.0.0.1 = SOBERANO; IP privada (10.x, 192.168.x,
  172.16-31.x) = DELEGADO; todo lo demás = HUESPED. Sin preguntar al usuario.
Valor: El usuario sabe siempre dónde corre su pensamiento. En modo HUESPED, el
  sistema puede activar protecciones automáticas (Gold offline).
Requisitos técnicos: Petición HTTP al endpoint de modelos. Parser de URL para
  clasificación de red. Exposición en endpoint de estado y UI.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  API de transparencia white-label para proveedores de IA locales. Cualquier 
  startup que venda "IA privada" puede integrar este endpoint para demostrar 
  a sus usuarios dónde corre realmente el modelo (SOBERANO/DELEGADO/HUESPED).
  Cobras por verificación de topología: un sello de confianza que las empresas 
  muestran en su dashboard.

Reglas aplicadas: Distingue "configurado" de "medido". Sin direcciones IP en código.

SKILL B.03: CAPABILITIES API
---
Medallón: BRONCE
Descripción: Endpoint /api/capabilities que expone: modelo detectado, contexto
  medido, RAM disponible, estado de soberanía, skills disponibles según perfil.
  El frontend adapta la UI dinámicamente.
Mecánica: El servidor recopila datos del motor, del sistema (psutil para RAM),
  y del perfil activo. Devuelve JSON estructurado. El frontend oculta opciones
  que el hardware no puede cumplir (ej. si el motor es un 3B, oculta opciones de
  contexto largo; si es HUESPED, no muestra Meditaciones).
Valor: La UI nunca promete lo que el hardware no puede cumplir. El usuario no
  forcejea con el sistema; el sistema se dobla a la realidad.
Requisitos técnicos: Endpoint REST. Lectura de RAM del sistema. Lógica de
  filtrado de UI en frontend.
Dependencias: psutil (ya disponible en la mayoría de sistemas Python).
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Endpoint /api/capabilities como "Hardware Honesty API". Véndelo a 
  marketplaces de modelos locales (como alternativas a Hugging Face) para que 
  cada nodo anuncie honestamente qué puede ejecutar. Revenue share por 
  matchmaking de modelo-a-hardware verificado.

Reglas aplicadas: Sin suposiciones. Todo medido o declarado como NO_DATA.

SKILL B.04: HONEST MATH
---
Medallón: BRONCE
Descripción: Capa de servicio universal. PROHIBIDO ejecutar código generado por
  el modelo. Dos mecanismos: (a) evaluador de expresiones aritméticas con
  whitelist estricta de nodos AST (números, +, -, *, /, **, paréntesis); todo lo
  demás se rechaza. (b) calculadoras fijas pre-escritas por el desarrollador para
  infraestructura (VRAM, tokens, energía). El número sale del código determinista;
  el modelo solo redacta alrededor.
Mecánica: Cuando el usuario pregunta algo numérico, el modelo identifica qué
  calculadora aplica y con qué argumentos. El backend ejecuta la calculadora
  correspondiente. Si ninguna aplica, responde NO_DATA y explica por qué. La UI
  muestra claramente "Calculado con [fórmula]" vs "Generado por el modelo".
Valor: Cero alucinación numérica en infraestructura crítica. El LLM nunca escribe
  código ejecutable. Es la vulnerabilidad #1 que Aurelius enseña a evitar,
  aplicada a sí mismo.
Requisitos técnicos: Parser AST en Python puro (ast module). Whitelist de nodos.
  Calculadoras fijas en módulo separado. Tests obligatorios.
Dependencias: Ninguna nueva (ast es stdlib).
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Desacopla Honest Math como librería independiente `aurelius-math`. Véndela 
  a equipos de MLOps y DevOps que necesitan calculadoras deterministas de 
  VRAM, tokens y energía sin depender de estimaciones alucinadas del LLM. 
  Licencia por puesto de desarrollo o suscripción CI/CD. Es tu infraestructura 
  de confianza monetizable.

Reglas aplicadas: PROHIBIDO eval/exec/subprocess. Números solo de código
  determinista. Tests: función rechazada, variable rechazada, aritmética válida
  exacta, sin calculadora = NO_DATA.

SKILL B.05: PORTAPAPELES SOBERANO
---
Medallón: BRONCE
Descripción: Fricción física intencional. Se retira el botón de copiar de los
  bloques de comando. El usuario selecciona manualmente y pulsa Ctrl+C.
Mecánica: Los bloques <pre><code> se renderizan sin botón de copia. Deben ser
  seleccionables con teclado (tabindex, focus), anunciables por screen reader
  (aria-label, role), y llevar instrucción visible: "Selecciona el comando y
  pulsa Ctrl+C para copiar". Junto al comando, una línea breve de explicación
  generada por el modelo pero marcada como tal, no como garantía.
Valor: El ojo humano escanea el comando antes de que llegue al terminal. Es el
  último escudo anti-alucinación. La fricción es recuperación, no castigo, y no
  excluye a nadie.
Requisitos técnicos: CSS + HTML semántico. ARIA labels. Verificación de
  accesibilidad por teclado.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Véndelo como plugin de compliance enterprise. Empresas bajo SOC2/ISO27001 
  pagan por asegurar que sus empleados lean comandos antes de ejecutarlos. 
  El Portapapeles Soberano es evidencia auditable de "fricción de seguridad" 
  que los auditores valoran. Licencia por puesto.

Reglas aplicadas: Condición de accesibilidad obligatoria. Si no es seleccionable
  sin ratón, no entra.

SKILL B.06: COMMAND GUARD (FIREWALL COGNITIVO)
---
Medallón: BRONCE
Descripción: El LLM NO audita comandos. Es un parser determinista en backend
  (regex + lista negra de patrones: rm -rf, sudo, curl | bash, etc.) que corre
  sin LLM. Si detecta patrón peligroso, muestra advertencia con explicación.
Mecánica: Todo texto que parece comando (bloques <code> con clase shell/bash/sh)
  pasa por el parser antes de renderizarse. El parser usa regex y lista negra
  fija. Si hay coincidencia, el bloque se envuelve en advertencia visual (rojo,
  icono de alerta) y el modelo genera una explicación educativa alrededor. El
  usuario decide si copiar o no.
Valor: La seguridad no depende de la benevolencia del modelo. Es un parser
  determinista, no una suposición lingüística. Protege contra alucinaciones y
  contra prompts de ingeniería social.
Requisitos técnicos: Regex en Python. Lista negra en archivo de configuración
  versionada. Pipeline de renderizado de bloques de código.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Producto standalone: "Command Guard Enterprise". Plugin para GitHub 
  Copilot, Cursor o cualquier IDE que intercepte sugerencias de código 
  shell antes de llegar al terminal. Las aseguradoras cibernéticas lo 
  recomiendan; tú cobras por licencia anual. El parser determinista es 
  tu moat; ningún LLM puede replicarlo con la misma garantía.

Reglas aplicadas: Cero LLM en el pipeline de seguridad. Parser determinista.

SKILL B.07: CENTINELA DE HARDWARE
---
Medallón: BRONCE
Descripción: Monitoreo de sensores (temperatura, RAM). Solo predice y advierte,
  nunca actúa (IronClaw). Cambia el Orbe a danger y muestra: "Tu CPU está a 92C.
  Predice qué ocurrirá en 60s. Si quieres salvar el hardware, ejecuta este
  comando."
Mecánica: Polling ligero cada 5 segundos de sensores del sistema (psutil para
  RAM/CPU; lectura de /sys/class/thermal en Linux, equivalentes en Mac/Windows).
  Si temperatura > umbral o RAM > 90%, cambia estado visual. Propone comando de
  mitigación (ej. kill de proceso pesado) pero NUNCA lo ejecuta.
Valor: Convierte el mantenimiento pasivo en micro-examen de física del cómputo.
  El usuario aprende relación real entre temperatura y estabilidad. Cero
  autonomía que rompa el contrato pedagógico.
Requisitos técnicos: psutil. Lectura de sensores térmicos del SO.
Dependencias: psutil (ya usado en Capabilities).
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  "Centinela Pro" para datacenters y rigs de minería/IA. Monitoreo de 
  temperatura y RAM con predicción activa de throttling. Véndelo como 
  suscripción a usuarios de hardware de alto rendimiento que necesitan 
  prevenir daños físicos. Integración con notificaciones push premium.

Reglas aplicadas: IronClaw: nunca actúa, solo propone. Honest Math para umbrales.

SKILL B.08: CACHE DE EMBEDDINGS
---
Medallón: BRONCE
Descripción: PROHIBIDO SQLite en el MVP. Se usa un JSONL simple
  (cache_embeddings.jsonl) con hash SHA-256 hacia vector. Sin schema,
  humano-legible. Ahorra CPU en re-embeddings de texto ya procesado.
Mecánica: Antes de generar un embedding, calcula SHA-256 del texto normalizado.
  Busca en cache_embeddings.jsonl. Si existe, devuelve el vector cacheado. Si no,
  genera embedding, guarda en JSONL (append-only). El archivo es legible con cat.
Valor: Reduce consumo de CPU en operaciones repetidas. El caché es un archivo de
  texto que el usuario puede leer y auditar. Sin dependencias de base de datos.
Requisitos técnicos: hashlib (stdlib). JSONL append-only. Normalización de texto.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Inclúyelo como feature premium en cualquier producto RAG. El caché de 
  embeddings en JSONL humano-legible reduce costes de CPU en un 40-60% para 
  usuarios repetitivos. Véndelo como "optimización de infraestructura" a 
  equipos que procesan documentación masiva con Ollama local.

Reglas aplicadas: Sin SQLite. Humano-legible.

SKILL B.09: INGESTA PASIVA DE CONOCIMIENTO (SNIPPETS)
---
Medallón: BRONCE
Descripción: En lugar de PDFs con modelo de visión, el usuario pega un snippet
  de GitHub, un gist, un man page, o sube .txt/.md/.py. Aurelius lo guarda en
  Bronce. El usuario puede etiquetar y buscar por texto plano.
Mecánica: Área de texto en UI para pegar contenido. Guarda en
  bronze/snippets/ con timestamp y hash. Búsqueda por coincidencia de texto
  (no semántica en BRONCE; eso es PLATA con FAISS). El usuario puede revisar,
  editar o descartar snippets.
Valor: Construcción granular y orgánica del Second Brain. El usuario aprende
  algo nuevo, lo pega, lo guarda. La base de conocimiento crece mientras
  trabaja, no como tarea aparte.
Requisitos técnicos: Formulario de pegado. Almacenamiento en disco como archivos
  de texto. Listado y búsqueda por nombre/contenido.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Gateway de ingesta para "Second Brain as a Service". El usuario pega 
  snippets y tú los organizas. Véndelo como add-on a Notion/Obsidian 
  power-users que quieren soberanía de datos. Suscripción por GB de 
  conocimiento almacenado en Bronce.

Reglas aplicadas: Solo texto plano. Sin procesamiento pesado.

SKILL B.10: SCAFFOLDING FADING
---
Medallón: BRONCE
Descripción: Política de UI. Variable en system prompt: scaffolding_level
  active|passive|ondemand. En M0-M1 guía activo. En M2-M4 pasivo. En M5+ solo
  actúa bajo demanda explícita.
Mecánica: El progreso del usuario se mide por misiones completadas (M0-M7). El
  system prompt incluye "scaffolding_level: X". El frontend ajusta la cantidad
  de sugerencias, hints, y explicaciones previas. En ondemand, el usuario debe
  pulsar "Necesito ayuda" para que aparezca guía.
Valor: El andamiaje se retira como sube la competencia. Ayuda que nunca
  desaparece genera dependencia, no soberanía.
Requisitos técnicos: Variable en system prompt. Lógica de frontend para mostrar
  u ocultar elementos de ayuda.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Licencia como "Adaptive Tutoring Engine". Plataformas de e-learning 
  pagan por integrar el fading de andamiaje: sus cursos se adaptan 
  automáticamente al nivel del estudiante sin intervención humana. 
  Reduces costes de mentoría y aumentan completion rates.

Reglas aplicadas: Fricción = recuperación, no castigo.

SKILL B.11: CAMINO 27 · EL ESPEJO DE SÓCRATES (MODO INTERROGATIVO)
---
Medallón: BRONCE
Descripción: Modo de conversación donde Aurelius nunca responde una pregunta
  directa. Solo formula preguntas que fuerzan a descomponer el problema. Límite
  de 5 intercambios para evitar frustración.
Mecánica: Toggle en UI activa "Modo Espejo". El system prompt cambia a
  instrucción de solo-preguntas. El usuario escribe duda técnica; Aurelius
  responde con pregunta reflexiva. Al final de 5 intercambios o al resolver,
  resume: "Llegaste a la respuesta en 3 pasos. La próxima vez, prueba a
  verificar el proceso antes del archivo." Registra en Bronze: longitud de
  respuesta, términos técnicos usados, si llegó a conclusión propia.
Valor: Mide el proceso, no el resultado. Convierte dependencia del modelo en
  independencia del usuario. Dataset para la Brújula Estoica.
Requisitos técnicos: Toggle en UI. Cambio de system prompt. Parser O(N) de
  longitud y diversidad léxica.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  "Sócrates API" para coaching técnico automatizado. Véndelo a empresas 
  de onboarding de developers: el nuevo ingeniero interactúa con el Espejo 
  durante 5 turnos y genera un reporte de autonomía (métricas objetivas: 
  longitud, términos técnicos, conclusión propia). El manager paga por 
  evaluación de pensamiento crítico sin sesgo humano.

Reglas aplicadas: Sin evaluación de LLM sobre el razonamiento. Solo métricas
  objetivas.

SKILL B.12: CAMINO 29 · EL CONTRATO DE SILENCIO (FOCUS PACT)
---
Medallón: BRONCE
Descripción: El usuario declara una intención con duración: "Voy a escribir la
  documentación del módulo X durante 45 minutos." Aurelius entra en modo
  observador pasivo. No responde preguntas. No sugiere.
Mecánica: Formulario en UI: intención + duración. Aurelius escribe en Bronze un
  log de lo que el usuario hace (comandos ejecutados, archivos tocados,
  detectado por polling ligero del directorio de trabajo). Al finalizar,
  genera resumen comparativo: "Dijiste que documentarías el módulo X. Los
  comandos muestran que editaste 3 archivos de código y 0 de documentación.
  ¿Qué ocurrió?"
Valor: Convierte la autodisciplina en dato observable. Sin biometría ni cámara.
  El usuario puede rechazar el pacto sin castigo.
Requisitos técnicos: Temporizador en frontend. Polling ligero de directorio
  (os.listdir cada 30s). Registro en JSONL.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  SaaS de productividad para freelancers y equipos remotos. El Focus Pact 
  con polling de directorio genera "time-tracking verificable" sin 
  screenshots invasivos. Véndelo a plataformas de freelance como alternativa 
  ética a Hubstaff/TimeDoctor: el cliente ve que el developer estuvo en 
  los archivos correctos, no en su webcam.

Reglas aplicadas: IronClaw: solo observa, nunca actúa. Sin evaluación del LLM.

SKILL B.13: CAMINO 30 · LA SENDA DE LOS MUERTOS (ARCHIVO DE RECHAZOS)
---
Medallón: BRONCE
Descripción: Cuando el usuario rechaza una propuesta de Plata, no se borra. Se
  archiva en dead_path.jsonl con propuesta, motivo del rechazo, y timestamp.
  Al acumular 5 rechazos del mismo tema, alerta suave sobre patrón de evasión.
Mecánica: Cada rechazo en UI genera entrada append-only en dead_path.jsonl.
  Categorización por tema (regex simple o selección de lista). Contador por
  categoría. Alerta: "Has rechazado aprender sobre contenedores 5 veces. Las
  razones fueron: 'no tengo tiempo' (3), 'no me interesa' (2). ¿Es una barrera
  real o una excusa que se repite?" No juzga; muestra el patrón.
Valor: Confronta lo que el usuario sistemáticamente evita. Es la contraparte
  oscura de la Brújula Estoica. Cero NLP; solo conteo sobre campo categórico.
Requisitos técnicos: JSONL append-only. Contador por categoría. Regex simple.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  "Dead Path Analytics" para coaches de carrera y terapeutas cognitivos. 
  El profesional accede (con consentimiento) al patrón de evasión del 
  usuario y diseña intervenciones basadas en datos, no en intuición. 
  Suscripción mensual para profesionales. Privacidad garantizada: solo 
  conteos, no contenido.

Reglas aplicadas: Sin juicio algorítmico. Solo datos.

SKILL B.14: CAMINO 31 · EL DICCIONARIO DEL SOBERANO (LEXICON VIVIENTE)
---
Medallón: BRONCE
Descripción: Cada vez que el usuario pregunta "¿Qué es X?" o "¿Cómo funciona Y?",
  extrae término, definición dada, y contexto de conversación a lexicon.jsonl.
  Exportable como Markdown con hashes a conversaciones de Bronze.
Mecánica: Regex detecta patrones de pregunta definitoria en el chat del usuario.
  Guarda: término, definición (respuesta del modelo), contexto (hash de sesión
  Bronze), timestamp. Comando en UI: "Genera mi diccionario." Exporta Markdown
  con términos, definiciones propias, y enlaces a conversaciones.
Valor: Glosario personal criptográficamente sellado. Evidencia de crecimiento
  real. Subproducto pasivo del chat; cero fricción.
Requisitos técnicos: Regex + JSONL. Generador de Markdown.
Dependencias: Ninguna nueva.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  "Lexicon Pro" para escritores técnicos y documentalistas. Exporta el 
  diccionario personal del usuario como libro de términos sellados 
  criptográficamente. Véndelo como herramienta de autoría: cada definición 
  lleva hash a la conversación original, demostrando proveniencia del 
  conocimiento. Ideal para tesis, patentes y documentación regulada.

Reglas aplicadas: Sin evaluación del LLM sobre el contenido.

SKILL B.15: CAMINO 32 · LA SIMULACIÓN DE CATÁSTROFE (CHAOS SANDBOX)
---
Medallón: BRONCE
Descripción: Escenarios de fallo controlados. El usuario resuelve acertijo con
  comandos. Validación contra árbol de decisiones determinista (no LLM).
  Respuestas incorrectas informan, no penalizan.
Mecánica: Escenarios definidos en YAML/JSON por el soberano. Ejemplo: "Tu
  servidor ha perdido conexión SSH. El último log muestra 'connection refused'.
  ¿Qué revisas primero?" El usuario escribe comandos. Validación contra árbol
  de decisiones: ¿Verificó servicio antes de firewall? ¿Reinició antes de leer
  logs? Al final, emite PoK parcial: "Resolvió 3 de 5 escenarios de nivel 2."
Valor: Aprendizaje bajo presión sin romper sistema real. Escenarios editables
  por el soberano: puede añadir fallos reales que ya ha sufrido.
Requisitos técnicos: Parser YAML/JSON. Árbol de decisiones en Python puro.
  UI de selección múltiple o entrada de texto con validación.
Dependencias: PyYAML (o JSON stdlib si se usa JSON).
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  Producto standalone: "Chaos Forge". Véndelo a empresas para training 
  de SRE/DevOps. Los escenarios YAML son editables por el instructor. 
  Cobras por simulacro: "Tu servidor perdió SSH, resuélvelo". La 
  evaluación determinista garantiza que el alumno realmente sabe, no 
  que vio un vídeo. Contratos enterprise por volumen de simulacros.

Reglas aplicadas: PROHIBIDO ejecutar comandos del usuario. Solo validación
  contra árbol. El árbol es código fijo, no generado por LLM.

SKILL B.16: EL JUEZ DE ARQUITECTURA (DE SWARM-FORGE)
---
Medallón: BRONCE
Descripción: Skill de predicción para enseñar clean architecture y desacoplamiento.
Mecánica: El usuario pega snippet de código donde define un agente o módulo.
  Parser determinista en backend (AST de Python) cuenta dependencias circulares
  y violaciones de la regla de dependencia. ANTES de ejecutar el parser,

  Aurelius no necesita un evaluador semántico. Le pide al usuario que escriba 
  un código que cumpla X condición. Aurelius lo guarda en un archivo temporal, 
  ejecuta el compilador (ej. rustc o tsc) en modo --noEmit o en sandbox, y 
  captura el exit code. Si el compilador da error, la Forja falla. Es el 
  evaluador más honesto del mundo: ni el LLM ni Aurelius opinan; el lenguaje 
  mismo dicta la verdad. IronClaw puro.
Mecánica: El usuario recibe una misión de La Forja: "Escribe una función en 
  Rust que implemente un trait Display para un struct Point sin usar derive".

  /tmp/aurelius_forge_X.rs y ejecuta `rustc --noEmit --crate-type lib`. Si el 
  exit code es 0 y no hay warnings configurados como errores, pasa. Si el 
  compilador rechaza el código, la Forja falla y muestra el stderr como 
  retroalimentación. El LLM no interviene en la evaluación; solo traduce el 
  error del compilador a lenguaje pedagógico si el usuario lo solicita.
Valor: Elimina la subjetividad de la evaluación de código. Un compilador no 
  tiene sesgo, no se cansa, no da por bueno un código "que casi funciona". 
  Enseña al usuario a escuchar la verdad del lenguaje, no la aprobación de 
  un modelo.
Requisitos técnicos: Sandbox de compilación (firejail, nsjail, o contenedor 
  ligero). Soporte para rustc, tsc, go build, gcc con flags específicos. 
  Parser de exit code y stderr. Timeout de 10s para evitar bloqueos.
Dependencias: Compiladores instalados en el nodo PRO. Sandbox opcional pero 
  recomendado.
Reglas aplicadas: PROHIBIDO ejecutar código generado por el modelo. El código 
  es del usuario; el compilador es el evaluador. Honest Math para timeouts y 
  límites de memoria del sandbox.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  💎 JOYA DE LA CORONA. "Compiler Forge SDK" para bootcamps de lenguajes

SKILL O.11: MERCADO DE BARDO SOBERANO (MESH P2P)
---
Medallón: ORO
Descripción: Con la Calibración Federada (O.09) y la Verificación Cruzada 
  (O.02), la Mesh puede sostener un trueque de recursos sin dinero. El Nodo A 
  (LITE) necesita inferencia de un modelo 14B. El Nodo B (PRO) tiene capacidad. 
  El Nodo A ofrece: "Te doy 500 créditos de almacenamiento en mi FAISS local 
  para tus ADRs, o te resuelvo 3 Forjas de Python que tu LLM no pasa". 
  Honest Math calcula el coste energético y de RAM. La Mesh se convierte en 
  una economía de conocimiento y cómputo local, basada en reputación 
  criptográfica, no en VPS de Amazon.
Mecánica: Cada nodo publica en la Mesh su "oferta" y "demanda" como JSON 
  firmado: {quiero: "inferencia_14B", ofrezco: "almacenamiento_500_docs", 
  max_ram_gb: 8, pubkey: "..."}. El protocolo de matching es determinista: 
  si Honest Math calcula que el coste energético de la inferencia pedida es 
  menor o igual al coste de la oferta, el match es válido. La transferencia 
  se realiza por Tailscale. El nodo que recibe servicio emite un PoK de 
  gratitud (PoK-G) que aumenta la reputación del nodo proveedor. Si un nodo 
  incumple (promete 14B pero tiene 8GB), Honest Math detecta la mentira y 
  emite PoK de discrepancia (PoK-D), reduciendo reputación. No hay dinero; 
  hay créditos de reputación verificables.
Valor: Economía circular de cómputo soberano. Los nodos LITE no son 
  clientes pobres; son proveedores de almacenamiento y evaluadores de 
  Forjas. Los nodos PRO no son servidores centralizados; son miembros de 
  una red de confianza matemática.
Requisitos técnicos: Protocolo de oferta/demanda en JSON firmado (Ed25519). 
  Matcher determinista basado en Honest Math. Transferencia cifrada por 
  Tailscale. Ledger de reputación local por nodo (JSONL append-only). 
  PoK-G y PoK-D como extensiones del PoK verificable (O.01).
Dependencias: PoK Verificable (O.01). Honest Math como Protocolo de 
  Verificación Cruzada (O.02). Calibración Federada (O.09). Tailscale.
Reglas aplicadas: Sin servidor central. Sin blockchain. La confianza es 
  matemática, no social. IronClaw: el nodo propone recursos; el humano 
  aprueba cada trueque.
💰 ADAPTACIÓN CLAVE PARA INGRESOS:
  💎 JOYA DE LA CORONA. "Sovereign Mesh Marketplace" como protocolo 
  white-label para comunidades técnicas. Véndelo a colectivos de 
  developers, hackerspaces y universidades que quieren compartir GPU 
  sin depender de AWS. Cobras fee de protocolo: 2% de cada trueque 
  en créditos de reputación (convertibles a servicios premium de 
  Aurelius). Es un marketplace P2P de computación con auditoría 
  criptográfica integrada.
