### I. DOCTRINA MAESTRA, PRINCIPIOS Y NAMESPACES UNIX

#### 1. LA VISIÓN FILOSÓFICA (LOS CINCO PILARES SOBERANOS)
El sistema **p0x** no es simplemente un stack de software; es un manifiesto técnico y existencial hecho silicio:
> *"El silicio es la frontera, la matemática es la ley, el carbono sella la verdad. Ante conflicto, el hardware y las inteligencias artificiales locales ganan siempre."* [81, 236, 263]

Esta doctrina se desglosa en principios inalterables inyectados en la base del preceptor [82, 264]:
*   **I. Soberanía Digital Absoluta (Digital Sovereignty)**: Tu máquina, tus modelos, tus datos, tu firma [82, 264]. La inferencia de IA local (Qwen mediante Ollama) corre completamente aislada en tu hardware físico, realizando llamadas locales HTTP y rechazando de raíz cualquier dependencia o exfiltración hacia la nube corporativa [82, 87, 264].
*   **II. Firma Humana Obligatoria (Human-in-the-Loop Signing)**: La máquina es un siervo lógico; el humano es la autoridad absoluta y la única fuente de legitimidad [83, 239, 264]. Ninguna alteración lógica, diff de repositorio, actualización de base de datos o ascenso de misión formativa se aplica automáticamente [83, 239, 264]. El sistema propone cambios en estado *spec_ready* (🟡) y calcula su SHA-256 [83, 239, 264]. El operador debe revisar el código y firmar físicamente el hash con su clave privada Ed25519 en frío, entregando una firma detached `.sig` [83, 239, 264]. El script `verify_pow.sh` valida esta firma antes de arrancar [83, 239, 264].
*   **III. Honestidad de los Sensores (Honest Sensors)**: Un valor nulo o ausente es infinitamente más honesto que una aproximación o un dato falso [84, 264]. Si un sensor, dongle USB o microcontrolador falla, el gateway detiene la simulación y el dashboard muestra el mensaje literal **NO DATA** en tipografía monospace roja parpadeante, reportando la causa y el timestamp (*last seen*) [84, 264]. Quedan estrictamente prohibidos los skeletons infinitos, los ceros falsos o los valores cacheados expuestos como datos frescos [84, 264].
*   **IV. Fricción Física Pedagógica (Portapapeles Soberano)**: La velocidad de asimilación exige detenerse. Eliminar la fricción elimina el entendimiento [85, 264]. Se prohíben los botones automáticos de copiar código de un solo clic [85, 264]. Las cajas de comandos obligan a la selección manual del texto y la combinación física **Ctrl+C**, forzando al ojo humano a auditar cada carácter antes de que este llegue a la terminal de ejecución [85, 264].
*   **V. La Brújula Estoica (Coherencia en Acción)**: La autodisciplina requiere datos objetivos de confrontación [86, 264]. El sistema lee tus propósitos maestros sellados en la capa Gold y analiza las conversaciones de tu capa Bronze [86, 264]. Si detecta que has dedicado tiempo a asuntos ajenos a tu intención declarada, te enfrenta amablemente a tus propios datos: *"Dijiste que querías aprender criptografía, pero has hablado más sobre temas de ocio. ¿Actualizamos el rumbo o corregimos tu disciplina?"* [86, 264].

### II. EL CATÁLOGO COMPLETO DE SKILLS AURELIUS (COMPILADO Y EVALUADO)

#### REGLAS DE CLASIFICACIÓN
*   **BRONCE**: Disponible en LITE (8 GB RAM). Barrera cero. Pedagogía pura. Sin FAISS, sin criptografía, sin red privada. Solo Python, JSONL, HTML/JS vanilla, y el modelo que elija el usuario [10].
*   **PLATA**: Requiere PRO o progreso en misiones. Añade persistencia estructurada, evaluación, FAISS, Gold poblado, o embeddings. No requiere red ni criptografía de infraestructura [10].
*   **ORO**: Requiere PRO + infraestructura avanzada: criptografía (Ed25519, AES-256-GCM), red privada (Tailscale), transferencia entre nodos, Mesh, o 32 GB+ RAM [11].

#### INVARIANTES DEL PROYECTO (Aplicables a TODAS las skills) [11]:
1. El modelo lo elige el usuario; el proyecto nunca lo fija.
2. PROHIBIDO eval/exec/subprocess con texto generado por el modelo o el usuario.
3. CERO direcciones IP, nombres de host o credenciales en código o config versionado.
4. Toda fricción debe ser predicción o recuperación; si solo impone coste, no entra.
5. IronClaw: el sistema propone; el humano ejecuta y firma.
6. Honest Math: los números salen siempre de código determinista; el modelo solo redacta.
7. Portapapeles Soberano: sin botón de copiar; selección manual obligatoria.
8. Command Guard: parser determinista (regex/AST); NUNCA el LLM audita seguridad.

*   **Descripción**: El servidor acepta `--perfil` con dos valores. El perfil NO fija el modelo; fija el contrato de recursos esperados (RAM mínima, contexto), la interfaz de escucha (loopback para LITE, red privada configurable para PRO) [12].

#### B.02: DECLARACIÓN HONESTA DEL MOTOR
*   **Descripción**: El servidor consulta al motor de inferencia qué modelo tiene cargado, su ventana de contexto y su ubicación. Expone tres estados derivados del endpoint configurado: SOBERANO (loopback local), DELEGADO (red privada), HUESPED (tercero) [13].

#### B.03: CAPABILITIES API
*   **Descripción**: Endpoint `/api/capabilities` que expone: modelo detectado, contexto medido, RAM disponible, estado de soberanía, y skills disponibles según perfil. El frontend adapta la UI dinámicamente [14].

#### B.04: HONEST MATH (EVALUACIÓN AST)
*   **Descripción**: Capa de servicio universal. PROHIBIDO ejecutar código generado por el modelo. Utiliza un evaluador de expresiones aritméticas con whitelist estricta de nodos AST (Abstract Syntax Tree) en Python puro (módulo `ast`) [15].
*   **Mecánica**: Cuando el usuario pregunta algo numérico, el modelo identifica la calculadora que aplica y el backend ejecuta el script de bajo nivel. Si no aplica, responde `NO_DATA` [15].

#### B.05: PORTAPAPELES SOBERANO
*   **Descripción**: Fricción física intencional. Se retira el botón de copiar de los bloques de comandos. El usuario debe seleccionar manualmente y pulsar **Ctrl+C** [16].

#### B.06: COMMAND GUARD (FIREWALL COGNITIVO)
*   **Descripción**: El LLM NO audita comandos. Es un parser determinista en backend (regex + lista negra fija de patrones: `rm -rf`, `sudo`, `curl | bash`, etc.) que corre sin LLM [17].
*   **Mecánica**: Todo texto que parece comando shell pasa por el parser. Si hay coincidencia de riesgo, el bloque se envuelve en una advertencia visual roja de peligro, delegando la ejecución en el operador [17].

#### B.08: CACHÉ DE EMBEDDINGS
*   **Descripción**: Se usa un JSONL simple (`cache_embeddings.jsonl`) con hash SHA-256 hacia el vector. Sin schema, humano-legible. Ahorra CPU en re-embeddings de texto ya procesado [19].

### III. ANÁLISIS DETALLADO DE LOS 11 REPOSITORIOS CLAVE

#### 1. ggerganov/llama.cpp (El Límite del Silicio Local) [285]
*   **Arquitectura de Grafo de Cómputo Estático (ggml)**: La biblioteca de tensores 'ggml' rechaza el despacho de ejecución dinámico en caliente. Construye secuencialmente en frío el grafo de operaciones `ggml_cgraph` (operaciones como `ggml_mul_mat` y `ggml_gelu`). El planificador calcula de forma global el tamaño de memoria temporal exacta requerido para todas las capas intermedias antes de realizar el primer cálculo, logrando la máxima eficiencia de caché y cero sobrecargas [285].
*   **Alocación Estática de Heap (ggml_gallocr)**: llama.cpp utiliza un alocador estático de memoria de grafo (`ggml_gallocr`): mide en frío el tamaño máximo de los buffers de activaciones, reserva un único bloque contiguo de RAM al arrancar y anula por completo el uso de `malloc()` y `free()` en caliente durante el bucle de inferencia [285].
*   **Optimización de Memoria (GGUF, mmap y Quants)**:
    *   *Formato GGUF*: Archivo binario con cabecera de metadatos tipada y alineación de bytes fija.
    *   *Memory Mapping (mmap)*: Mapea el archivo GGUF directamente en el espacio de direcciones de memoria virtual del kernel. Los pesos se cargan página por página bajo demanda de la CPU (*page faults*), reduciendo la RAM física necesaria al inicio [285].
    *   *K-quants*: Precisión mixta por superbloques de 256 coeficientes (ej. Q6_K para capas críticas de atención y Q4_K_M para feed-forward) [285].
    *   *IQ-quants (Importance Matrix)*: Aplica cuantizaciones mixtas de alta compresión por debajo de los 2 bits por peso basándose en una matriz de peso semántico calculada en gradientes [285].
*   **Mitigación de Vulnerabilidades del Parser**: Protege al sistema contra exploits de desbordamiento de enteros (Integer Overflow) en el parser de cabeceras GGUF en C (CVE-2026-33298, CVE-2026-27940). El sistema paralelo de `verify_pow.sh` calcula obligatoriamente el checksum SHA-256 de los modelos y su firma detached Ed25519 antes de cargarlos en memoria [285].

#### 2. karpathy/llama2.c (Inferencia Minimalista e Hilos C99) [286]
*   **Simplicidad en C99**: Inferencia de transformers en menos de 1000 líneas de C99 puro sin dependencias externas ni compiladores pesados [286].
*   **Alocación de Estado Contiguo**: Define tres estructuras alineadas en el heap (`Config` de 28 bytes, `TransformerWeights` de punteros float directos y `RunState` para activaciones). Mapea el disco mediante `mmap()`, permitiendo que el tiempo de carga del modelo sea instantáneo sin deserializaciones en RAM [286].

#### 3. anyproto/anytype-ts (Identidad Local y Sincronización P2P) [287]
*   **Topología any-sync**: Sincronización descentralizada local-first. La identidad completa del usuario se deriva localmente mediante criptografía asimétrica de una frase mnemónica de 12 palabras [287].
*   **Criptografía en el Árbol de Cambios**: Cada documento es un árbol de Merkle inmutable de modificaciones locales firmadas con Ed25519 y encriptadas de forma simétrica mediante AES-CFB, permitiendo la transferencia segura de bloques por cualquier red [287].
*   **Desacoplamiento gRPC**: El frontend en React delega la persistencia física en un middleware local en Go, comunicándose asíncronamente mediante gRPC sobre sockets locales para no bloquear el hilo de renderizado visual [287].

#### 4. syncthing/syncthing (Sincronización por Deltas y SQLite WAL) [288]
*   **Protocolo BEP (Deltas Sync)**: El Block Exchange Protocol (BEP) divide cada archivo en bloques lógicos calculados mediante hashes SHA-256. Al sincronizar de forma offline, los nodos intercambian únicamente las firmas de los hashes y descargan exclusivamente los bloques faltantes, previniendo picos térmicos en el procesador [288].
*   **SQLite WAL para Persistencia**: Reemplazó el uso de bases clave-valor por SQLite WAL para garantizar integridad transaccional ACID contra apagones físicos y caídas de tensión de las baterías [288].

#### 5. automerge/automerge (CRDT y Compresión Columnar) [289]
*   **Rust & WASM**: El motor matemático de colaboración CRDT está escrito en Rust y compilado a WebAssembly. El almacenamiento en memoria de trabajo adopta una compresión columnar binaria (estilo Apache Parquet) que reduce la RAM física activa en un 95% [289].
*   **Persistencia Diferencial**: Escribe instantáneamente transacciones incrementales mediante la primitiva `save_incremental()`, mitigando el desgaste de escritura de los discos NVMe y SD [289].

#### 6. simonw/llm (Orquestación CLI en Python y Logs SQLite) [290]
*   **Log Relacional inmutable**: Registra de forma transaccional cada prompt, respuesta, timestamps e identificadores de modelo en una base de datos local relacional SQLite (`logs.db`), liberando el contexto de la RAM [290].
*   **Sistema Modular desacoplado**: Arquitectura basada en "entry points" de Python que desacopla por completo el backend de inferencia del hilo administrativo principal [290].

#### 7. antirez/dump1090 (Ingesta de Radiofrecuencia en C Puro) [291]
*   **Ingesta por DMA USB**: Adquiere señales electromagnéticas a 1090 MHz mediante dongles RTL-SDR acoplados a USB. Almacena las muestras en un buffer circular estático prealocado al arranque mediante acceso asíncrono directo a memoria (DMA) [291].
*   **Lookup Tables Trigonométricas**: Precalcula los valores trigonométricos complejos de amplitud en una tabla estática en frío (`mag_lut`), reduciendo la estimación de magnitudes a lecturas de arrays directas en hardware, eliminando el cómputo de raíces cuadradas y manteniendo el consumo de CPU de la ARM por debajo del 5% [291].

#### 8. codenotary/immudb (Inmutabilidad por Árboles de Merkle) [292]
*   **Log Tamper-Proof**: Estructura de almacenamiento clave-valor append-only en Go donde cada nueva fila se concatena criptográficamente en un hash con la fila anterior formando un árbol de Merkle [292].
*   **Consistency e Inclusion Proofs**: Permite realizar validaciones matemáticas locales fuera de red para verificar de inmediato que los datos históricos no han sido mutados o borrados en el disco físico [292].

#### 9. mtlynch/tinypilot (Renderizado de Interfaz sin Latencia) [293]
*   **Captura de Video Directa**: Control KVM de bajo consumo en Raspberry Pi que captura video por hardware interactuando directamente con el controlador del kernel `v4l2` (vía MJPEG/WebSockets) [293].
*   **Interfaz Stateless**: Prescinde por completo de Node.js, Webpack o frameworks pesados, inyectando las tramas de control de teclado del operador directamente en el driver OTG de Linux (`/dev/hidg0`) [293].

#### 10. betta-tech (Agentes en Disco y Sintaxis EARS) [294]
*   **Persistencia de Estados en Disco**: Los estados intermedios y colas de tareas de los agentes se escriben de manera transaccional en disco antes de procesarse en RAM, evitando pérdidas de contexto ante cortes de energía [294].
*   **Sintaxis EARS**: Los requisitos operativos y de herramientas se redactan bajo las directrices lógicas de la sintaxis estricta EARS (WHEN / IF / THEN / SHALL) para anular alucinaciones de diseño [294].

#### 11. Gentleman-Programming (Engrams y SQLite FTS5) [295]
*   **Memoria en Engrams**: Organiza el conocimiento de desarrollo en fichas atómicas relacionales de cuatro campos (What, Why, Where, Learned) [295].
*   **SQLite FTS5**: Almacena y realiza búsquedas de texto virtual completo de forma instantánea y totalmente offline [295].

#### 4. CATEGORÍA: [ARQUEOLOGÍA]
Catálogo de ideas de visualización, andamiajes pedagógicos y tecnologías que han sido descartadas sistemáticamente durante el desarrollo y censo de p0x por atentar contra la doctrina, presentar vulnerabilidades de red o saturar el silicio [99]:
*   **Marco de Neón de Celdas (El Nexo)**: Descartado por competir visualmente con el contraste de las telemetrías reales y consumir ciclos de pantalla innecesarios. Reemplazado por borde de 1px con glow reservado exclusivamente a cifras vivas [99, 138].
*   **Fondo Negro Plano de la Mesa en Le Jardin**: Vetado por el soberano por considerarlo "poco agraciado". Reemplazado por madera clara y pergamino generados mediante CSS vanilla de gradientes lineales, eliminando el coste de cargar imágenes de textura pesadas en la RAM [99, 138].
*   **Sopa de Etiquetas en el Second Brain**: La acumulación de títulos de engramas convertía el grafo en un elemento de ruido ilegible. Reemplazado por la Ley de Detalle por Zoom (LOD), donde los nombres de los nodos solo se renderizan según el grado de conectividad y el nivel de zoom físico de la pantalla [99, 138].
*   **Barras de Progreso Lineales de Agentes**: Descartadas en el Sínodo por su ambigüedad; reemplazadas por chips con métricas reales [99, 138].
*   **localStorage como Persistencia Única (Le Cahier)**: El preceptor vetó de forma absoluta el uso del navegador del cliente como almacén persistente de las notas de Le Jardin. Reemplazado por llamadas asíncronas HTTP POST al disco del nodo de red (`diary_sealed/`), reduciendo localStorage a un buffer temporal offline de contingencia con reconciliación de datos automática al arranque [99, 138].
*   **Grilla Multicolumna Estática o 4x4/6x6 de L'Herbier**: Descartada para evitar constantes re-maquetaciones y saltos de interfaz. Reemplazada por una tira horizontal deslizable con snaps de vista adaptable [99, 138].
*   **Uso del Daemon immudb**: Vetado por atentar contra la integridad térmica. Su colector de basura en Go y el cálculo continuo de hashes Merkle sobrecargaban de forma extrema los procesadores ARM de bajo consumo. Reemplazado por la inyección matemática de los árboles de Merkle dentro de la SQLite local utilizando triggers nativos en C [99, 151].
*   **Servidores Flask Monohilo y Puertos TCP Abiertos de dump1090 (30002/30003)**: Eliminados por carecer de autenticación mutua, cifrado y firmas criptográficas, exponiendo los dongles SDR a inyecciones remotas de datos aéreos y barcos falsos. Reemplazados por el aislamiento estricto de dump1090 de la red LAN y canalizando la telemetría aérea asíncronamente en loopback por FastAPI local [99, 150, 152].
*   **Uso de `thermal_zone0` como sensor de CPU para el Ryzen**: El uso de `thermal_zone0` en el Beelink Ryzen del Soberano devolvía de forma deshonesta 20°C fijos constantes correspondientes al driver ACPI genérico del SO. Reemplazado por la lectura real del bus `k10temp` expuesto en `hwmon3/temp1_input` [109, 198].
